# ARCH-07 migration/permissions — design only

Không sửa001–003 hoặc các target packages đã chốt. Số004+ phân bổ khi viết actual SQL; SQL/upgrade/restore/grants NOT RUN. Kế thừa [auth migration](../target-t1-auth/migration-plan.md).

1. Capture physical schema/actual indexes/checks trên disposable synthetic DB, verified backup trước upgrade. Add new fields nullable first và2control tables; real backup chỉ supported sau stable token migration/validation, không derive tokens từ email/amount hoặc assign token mới khi restore.
2. Backfill CSPRNG256bit recovery_token once per identity/workspace/device, enforce pertable uniqueness; recovery_control_epoch>=0 độc lập auth_epoch/deviceEpoch/recovery_epoch. Set existing workspace active chỉ khi verified current state không pending erase/revoke; no blanket reactivation. recovery_reset_required=false chỉ initial clean active state, restore sets true.
3. Add workspace access_state guard tới mọi finance read/mutation/worker/tool cùng transaction scope. RLS/narrow function must avoid recursive workspace policy lookup, spoofable arbitrary caller role và pool leakage; actual SQL test required. No ordinary owner/admin route được chuyển erasing→active.
4. Migrate recovery_journal scope_kind/environment/key/signature metadata; historical workspace_token becomes compatibility alias targetToken. Replace old UNIQUE(workspace_token,epoch) với UNIQUE(scope_kind,workspace_token,epoch), không break append-only bằng UPDATE checkpoint_ref; new delivery table holds ack/progress. Legacy unsigned records không tự become independent proof; synthetic legacy only/quarantine nếu không verify.
5. Recovery coordinator gets append journal, narrow delivery-state update/read, key usage+off-host append; no broad ledger SELECT/DELETE. erasure profile receives owner-approved per-scope purge procedures, fixedsearch_path/limited EXECUTE; ordinary retention denied active finance erase and deny-record deletion. Ops reads aggregate safe pending/error state, no tokens/eventbody/receipt/user IDs/secret reference dump.
6. erasure_requests parent_request_id selfFK restrict, no FK erased identity/workspace. Freeze children under identity/ownership locks before deleting parent; each child same original35day horizon, parent cannot complete early. Enforce parent scope=identity, child scope=workspace, identity parent has no parent, no self-link/cycles; a child cannot change parent or extend the inherited deadline. A self-FK alone does not enforce these rules: use narrow locked procedures and constraint checks with negative tests. Repeated requests for an already erasing target, including a new request key, reuse the existing workflow or its earliest accepted deadline under the same target lock; no new clock or replacement child inventory. delivery journal FK restrict, bounded attempts/state/CHECK; anchored requires receipt/sequence verified application+procedure boundary. Bytes/schema checks eventbody<=8192, no arbitrary metadata.
7. Indexes: pertable recovery_token UNIQUE; journal scope+target+epoch UNIQUE; delivery journal UNIQUE, pending-state/updated_at partial index; erasure scope+target+request-key UNIQUE, parent_request_id, backup_purge_due_at WHERE notcompleted, no secret/finance JSONindex. Bounds on sequence/epoch counters safe integer until versioned string contract change.
8. Validate same-key publication replay/witness crash/local commit race, actual deny before reads/jobs, erasure FK/pin dependency closure, expired snapshot+actual pack prune, current-head chain and all-token invalidation onrestore. No failed SQL run accepted as design proof. Rollback never lowers control/auth/device/recovery fences or resurrects erased rows/credentials; rollforward repair preferred.

Model/DDL counts are not completeness metrics. Full domain SQL correctness tiếp ARCH-08/09; key/witness/backup deployment tiếp security spikes/ARCH-13. No network call while holding DB transaction/locks; publication control is an idempotent deny outbox, not a second lease-based J2 financial dispatcher.
